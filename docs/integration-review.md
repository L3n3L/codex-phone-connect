# Codex 手机电脑桥接对接复盘

更新时间：2026-10-06

## 1. 目标

手机浏览器输入文字，电脑本地程序把文字提交到用户当前打开的 Codex 桌面窗口。

第一阶段只做：

- 原生 WPF 校准窗口；
- 局域网 HTTP 接收入口；
- 扫码进入的最小手机输入页；
- 输入框和发送按钮的相对坐标保存；
- 串行任务边界。

第一阶段不做：

- Thread 列表、Thread ID 识别和历史渲染；
- Codex 回复同步；
- 云服务和账号系统；
- 通过 UI Automation 读取 Codex 内部 Web 控件。

## 2. 已验证事实

### 2.1 Windows UI Automation

对当前 ChatGPT/Codex 桌面进程进行只读 UIA 检查后，窗口树能看到 Chromium 外壳和 `RootWebArea`，但没有可用的聊天 `Edit` 控件和发送 `Button` 控件。因此不能把 UIA 的控件属性作为主链路。

### 2.2 Codex app-server

独立 app-server 进程可以完成初始化、Thread 列表和已知 Thread 的读取；已知 Thread 的历史可以由外部页面渲染。但这不等于可以读取桌面端当前选中的 Thread，也不能默认加入桌面端当前 writer。

一次对当前活跃 Thread 的外部写入尝试返回 `already has an active writer`，说明桌面端正在写入时存在并发写入限制。因此第一阶段不把 app-server 写入和桌面 UI 注入混在一起。

### 2.3 本机环境

- Windows 11
- .NET SDK 8.0.408
- WPF runtime 已安装
- 适合使用 C# / .NET 8 / WPF 做桌面端

## 3. 稳定的第一阶段架构

```text
手机浏览器
    │ POST /api/jobs
    ▼
Bridge.exe（WPF）
    ├─ 校准 UI
    ├─ 局域网 HTTP 服务
    ├─ 单线程任务队列
    └─ Windows 输入适配器边界
           │
           ▼
      Codex 桌面窗口
```

## 4. HTTP 契约

### `GET /api/status`

返回 Bridge 是否运行，以及手机应使用的访问地址。

### `GET /`

返回最小手机输入页。二维码编码的就是这个地址，手机和电脑在同一 Wi-Fi 时可以直接打开。

### `POST /api/jobs`

请求：

```json
{
  "text": "要发送给 Codex 的内容",
  "requestId": "手机端生成的唯一 ID",
  "token": "局域网配对码"
}
```

第一阶段返回：

```json
{
  "jobId": "服务器生成的任务 ID",
  "status": "queued"
}
```

## 5. 校准数据

保存相对于 Codex 客户区的比例，不保存绝对屏幕坐标：

```json
{
  "inputPoint": { "x": 0.50, "y": 0.92 },
  "sendPoint": { "x": 0.94, "y": 0.92 }
}
```

这样可以适应窗口移动和大小变化；DPI 或布局变化后允许重新设置。

## 6. 会话边界

Bridge 的目标是“发送瞬间 Codex 当前选中的会话”。它不承诺识别 A/B Thread：

```text
Codex 当前选中 A → 手机发送 → A
Codex 切换到 B   → 手机发送 → B
```

如果用户在任务排队期间切换会话，Bridge 无法从 UIA 确认 Thread 身份。任务必须串行，并在目标窗口不是 Codex 时拒绝发送。

## 7. 风险和处理

| 风险 | 处理 |
| --- | --- |
| Codex 没有在前台 | 拒绝发送，不发送到其他应用 |
| 窗口位置变化 | 使用客户区比例坐标 |
| DPI/显示器变化 | 允许重新设置坐标 |
| 多条消息并发 | 单线程队列和发送锁 |
| 剪贴板恢复过早 | 粘贴后等待，并仅在剪贴板仍是本次内容时恢复 |
| 局域网不可访问 | 显示实际地址，并提示 Windows 专用网络防火墙 |
| 多网卡选错地址 | 优先选择有默认网关的物理网卡，避免使用 VMware/TAP 等虚拟网卡 |
| 锁屏或权限级别不同 | 标记失败，不伪称已发送 |

## 9. 验收顺序

1. WPF 窗口能启动并显示局域网地址。
2. 两个校准按钮能记录 Codex 窗口客户区比例坐标。
3. 手机页面能调用 `/api/jobs`，Bridge 能收到并排队。
4. 在用户本机手动验证粘贴和发送。
5. 再处理配置保存、重校准、安装和防火墙提示。
