# Wi-Fi / USB 多入口对接执行复盘

更新时间：2026-10-26

## 目标与现状

用户要求：有几个有效入口就展示几个，每个入口同时展示地址和二维码，无需选择连接方式。

现有 Kestrel 服务已监听 `0.0.0.0:8787`。不足是 `MainWindow.GetLanAddress()` 仅在启动时选一个 IP，界面固定写着“同一 Wi-Fi 打开”，没有处理 USB 插拔、网卡断开和地址变更。

## 核心数据流

```text
Windows 网卡 / IPv4 状态
    ↓ 启动扫描、网络事件去抖、定期补偿扫描
NetworkConnectionDiscovery → NetworkConnectionMonitor
    ↓ 全量、有序、去重的有效地址快照
MainWindow → 每个地址独立生成二维码 → 手机连接区
    ↓ 同步地址快照
BridgeWebServer /api/status

手机访问任意一个可达地址
    ↓ Wi-Fi、有线局域网或 USB 网络共享
同一个 0.0.0.0:8787 服务
    ↓ 带明确 agentId 的发送 / 滚动请求
原有命令队列 → 对应桌面智能体窗口
```

连接列表用于发现服务地址，不限制 HTTP 监听范围，也不决定命令发送给哪个智能体。手机请求仍使用当前页面来源下的相对 API 路径。

## 地址规则

- 只收集状态为 Up 的 Wi-Fi / Ethernet 类网卡的有效单播 IPv4。
- 排除回环、链路本地 `169.254.*.*`、未指定、广播和组播地址。
- 排除常见 VPN、隧道、VMware、Hyper-V、VirtualBox、WSL、容器等虚拟接口。
- 虚拟接口和 USB 类型通过设备描述/接口名称识别，属于常见设备规则；未识别的厂商自定义接口可能需要后续补充规则。
- USB 网络共享通过 RNDIS / Internet Sharing / 手机设备等描述识别，不能仅依赖 Ethernet 类型。
- Wi-Fi 和普通有线网卡即使没有默认网关，也可能承载局域网访问，因此不强制要求网关。
- 同一 IP 去重，每张网卡有多个有效 IPv4 时分别展示；不写死最多两个。
- 按类型、接口名和 IP 稳定排序，避免二维码反复换位置。
- “有效入口”表示本机具有可供访问的地址，不能证明手机已连通；防火墙、VPN 和手机路由仍影响可达性。

## 生命周期与并发

- 网络发现、网络变化监听、WPF 二维码展示分别负责各自逻辑。
- 系统网络事件合并后刷新，另有低频扫描补偿未收到的事件；快照没变化时不重绘二维码、不重复记日志。
- 网卡扫描在后台进行，WPF 通过 Dispatcher 更新界面。
- 服务关闭时解除系统事件并释放计时器；关闭期间忽略延迟的界面刷新。
- 地址发现失败保留上一次快照并记录错误，避免把扫描失败误报成全部断网。
- HTTP 状态增加 `addresses` 数组；原 `address` 字段保留为首个地址以兼容现有调用。

## 用户可见行为

- 只有 USB：显示 USB 地址和二维码。
- USB、Wi-Fi 同时在线：同时显示两个入口，服务同时接收两条路径的请求。
- 拔掉 USB：对应卡片消失，剩余局域网入口继续展示；服务继续运行。
- 没有有效地址：隐藏二维码，显示“暂无可用连接地址”。
- 重新插入 USB / 连接 Wi-Fi：自动展示新地址，包括 DHCP 分配的新 IP。
- 窗口随地址数量调整高度，超过屏幕可用空间时滚动展示，避免内容裁切。
- 手机已打开的 USB 页面在拔线后仍指向旧地址，需重新打开可达入口；已进入电脑队列的命令仍可能执行，连接断开不触发自动重发。

## 验证与交付

- 编译通过，检查现有手机粒子与目标路由代码无改动。
- 用本机真实网卡验证 USB 地址入选、断开的 WLAN 和 VMware 接口不入选。
- 检查单入口、多入口和无入口的 WPF 布局及二维码内容。
- 通过 HTTP 状态接口检查地址数组与旧字段兼容性。
- 真机拔插 USB 和手机访问需要用户后续实测，不能以电脑侧本机请求替代。

## 实施与验证结果

- 新增 `NetworkConnectionDiscovery`，输出与 WPF 无关的地址模型；`NetworkConnectionMonitor` 负责系统事件、350ms 去抖、5 秒补偿扫描和变化去重。
- 新增 `ConnectionEntryViewModel`，每条入口生成二维码；窗口复用未变地址的二维码，移除断开网卡对应的卡片。
- WPF 使用列表模板按入口数量展示；窗口自动调整高度，内容超过当前显示器工作区时可滚动查看，增长后调整窗口位置以保留底部控件。
- `BridgeWebServer` 使用原子替换的地址数组；`/api/status` 的新数组和旧单地址字段来自同一快照。
- Release 编译成功，0 警告、0 错误。
- 本机实查只发现一个 USB 网络共享入口；断开的 WLAN、有线网卡和两个处于 Up 状态的 VMware 虚拟接口均未展示。
- 用临时验证程序检查 WPF 的 0、1、2、7 个入口快照；无入口时移除二维码，多入口保留全部卡片，7 个入口可以滚动查看。
- 用 OpenCV 解码实际 USB 与示例 Wi-Fi 二维码，均匹配对应 URL。
- 验证后台监听首次发布、5 秒扫描期间无变化不重复发布，并完成释放。
- 临时 HTTP 服务验证了 `/api/status` 新旧字段、空地址/恢复地址时服务继续运行、实际 USB 网卡 IP 和回环地址均可进入同一个监听器，以及正式手机页面加载。
- 现有手机粒子页、`PhoneAgentShell`、`AgentInputAdapter`、`BridgeJobQueue` 没有代码差异。
- 临时验证程序和截图位于仓库外，没有增加生产依赖或提交个人网络信息。
- 尚未代替用户完成手机真机访问、物理拔插 USB 及恢复 Wi-Fi 的验证；电脑侧 HTTP 验证不能证明手机侧路由和防火墙一定放行。
